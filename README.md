## 一、为什么做这个产品

跨境交付最容易产生风控盲区的时刻，往往在客户口头说「没问题」之后：

> *"The V2 sample looks good. Once QA signs off on the test report, we'll release 50% of the milestone balance. Please include five extra units at no additional charge."*

这封看似正向的邮件同时隐含三件不同的事：**验收仍有前置条件、另一半尾款未给出排期、额外 5 台尚未单独报价**。普通的邮件翻译或摘要工具，极易把这些关键商业边界抹平。

**GlobalEcho** 将买方原话、当前交付版本、付款台账与可回查的同行经验串联在同一条工作流中，核心原则是：

> **AI 辅助找证据、拆状态、拟回信；业务员核对合同与凭证，做最终决策（Human-in-the-Loop）。**

## 二、核心能力与设计边界

| 模块 | 核心机制与边界 |
| :--- | :--- |
| **来信取证与状态护栏** | 确定性规则引擎与 **DeepSeek V4.1 Flash（结构化语义抽取）+ DeepSeek V4 Pro（深度审单推理）** 分级协作；识别验收条件、付款限制、增项与版本冲突，**解耦维护「交付验收 / 付款排期 / 实际到账」三类状态**，模型不可直接越权结项（`canClose` 由规则护栏把关） |
| **多轮审阅与状态继承** | 支持多轮邮件连续跟进，自动继承尚未结清的分期金额、前置条件与撤回/重批记录，严格区分 QA 签核与增项批准 |
| **双源检索增强** | 接入**知乎官方开放平台检索**（同行实战依据，明确区分来源摘录与适用前提）以及 **multilingual-e5-small（384 维）+ PGlite / pgvector** 本地相似案例检索 |
| **人机协同回信与核验单** | 仅在用户人工核对并采纳依据后，生成可编辑英文回信草稿与核验清单；同类意图自动去重，完整保留人工修改 |
| **本地知识沉淀与隐私保护** | 个人来信档案与订单台账基于浏览器本地存储，结合核验反馈动态优化推荐排序，不自动上传服务端向量库；密钥严格隔离于服务端环境变量 |

## 三、系统架构与数据流

```text
买方来信 + 当前交付版本与付款台账
    │
    ▼
[确定性规则引擎]  ◀──▶  [DeepSeek V4.1 Flash 结构化抽取 + DeepSeek V4 Pro 深度审单推理]
    │  (状态护栏：解耦验收 / 付款排期 / 实际到账，禁止模型直接结项)
    ▼
[双源证据检索与本地知识沉淀]
    ├─ 知乎开放平台检索（同行经验与适用前提）
    ├─ multilingual-e5-small + PGlite/pgvector（相似案例语义召回）
    └─ 本地来信档案关联与人工核验反馈排序
    │
    ▼
[Human-in-the-Loop 人工核对采纳]
    │
    ▼
可编辑英文追问回信 + 结构化核验清单 → 多轮持续跟进
```

- **技术栈**：Next.js (TypeScript / React) · Python & TypeScript 双端规则护栏 · `DeepSeek V4.1 Flash` / `DeepSeek V4 Pro` · `multilingual-e5-small` · `PGlite / pgvector`
